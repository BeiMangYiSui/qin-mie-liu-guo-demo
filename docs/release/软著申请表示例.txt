三、软件用途与开发目的
--------------------------------------------------------------------------------

3.1  开发目的：
     通过原创历史题材叙事、分支选择与轻量回合制战斗，呈现角色在战争
     任务中的方法选择、代价承担与后续影响。

3.2  主要功能：
     1) 章节剧情阅读（含序章与第一章分支剧情）
     2) 分支选择（关键选择点写入 StoryFlags，影响后续剧情与战斗）
     3) 回合制战斗（3v3~3v6，依据 BattleConfig 配置胜利/失败条件）
     4) 教学战斗（序章郑地伏杀，三项目标数值上不可全成）
     5) 火场救援、追截战斗、撤离战等特殊玩法
     6) 章末结算与史乘对照（C2 解锁前两张史乘卡，C8 解锁后两张）
     7) 本地存档（3 个手动槽位 + 战前自动存档 + 战败回卷）
     8) 场景 BGM、角色配音、战斗音效管理
     9) 资源加载与移动端音频解锁

3.3  行业应用：互联网单机剧情游戏

3.4  技术特点：
     基于 React 19 + TypeScript + Vite 7 的浏览器 Web Demo；
     提审版将适配微信小游戏 / 抖音小游戏运行时；
     核心业务逻辑（剧情、战斗、存档）为纯函数实现，UI 层与业务层解耦；
     所有存档仅本地存储，不上传开发者服务器。

3.5  创新点：
     - 三人固定小队，无等级、无装备的轻量战斗设计
     - 战斗目标不止全歼：护副本、夺明卷、救人、守退路
     - 战败旁白以卷回点回到战前，不扣血扣档
     - 历史题材分支剧情与 4 张史乘对照卡

九、当前不能做的事（重要警示）
--------------------------------------------------------------------------------

9.1 不要先用一个名字申请软著，再换一个名字创建小游戏
     - 软著名称与小游戏名称必须从申请阶段就保持完全一致
     - 软著下发后改名需要走变更流程，耗时 30~60 天

9.2 不要用个人微信号或抖音号直接当作平台账号
     - 必须先注册小游戏专用账号（微信公众平台 / 抖音开放平台）
     - 账号主体与著作权人保持一致

9.3 不要在没有审核版前先做支付/内购/虚拟货币
     - 首版 V1.0 必须无任何商业化
     - 后续接入需在平台官方 SDK 通过后

9.4 不要把当前 Vite dist 目录直接作为小游戏包上传
     - 需迁移到小游戏运行时（Canvas / WebGL）
     - 资源需打入小游戏资源目录或使用官方白名单 CDN

9.5 不要在软著/平台提交时使用未确认授权的 AI 图、AI 音乐、第三方字体
     - AI 生成内容的版权归属复杂，建议替换为原创或商业授权素材
     - 第三方字体需确认可商用授权

9.6 不要为了通过而选择不符合实际玩法的游戏类目
     - 实际玩法是叙事策略 + 回合制战斗
     - 类目应填「游戏软件 / 角色扮演与策略类」

9.7 不要等软著证书下发后再开始准备小游戏迁移
     - 软著审查周期 30~60 天
     - 建议同时进行：注册账号 + 准备迁移 + 提交软著

9.8 不要在所有材料中混入真实身份证号、手机号以外的敏感信息
     - 仅在申请表主体信息栏填写真实信息
     - 源代码、文档中不出现任何敏感数据
