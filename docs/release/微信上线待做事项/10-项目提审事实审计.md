# 10 — 当前项目提审事实审计

审计日期：2026-08-05  
审计范围：仓库源码、`game.json`、微信平台适配器、当前 `dist-minigame` 产物和发布文档。

## 已具备

- 已有微信平台存储、音频、图片、分享和路由适配器骨架。
- 小游戏构建时 `SOCIAL_READY` 强制关闭，可隐藏站外社交入口。
- 小游戏模式下媒体路径计划改为包内相对路径。
- `game.json` 当前未声明任何权限，`requiredPrivateInfos` 为空数组。
- 当前业务无登录、支付、广告、聊天、排行榜和用户自由输入。
- 本地存档只保存游戏状态，不主动上传服务器。
- 已有软著源码和设计说明生成脚本以及多份发布材料底稿。

## 阻塞项

### 1. 当前产物不是可直接运行的微信小游戏工程

`src/main.minigame.tsx` 仍使用 React DOM 的 `createRoot`、`document.getElementById`、`window.location` 和 HTML/CSS 界面。标准微信小游戏运行环境不是普通浏览器页面，当前产物也没有形成完整的 `game.js` / Canvas 运行入口。因此“Vite 构建成功”不等于“微信开发者工具可运行并提审”。

### 2. 包体约 73 MB

当前 `dist-minigame` 复制了大量图片、BGM、音效和语音资源，整体约 73 MB。现有清理脚本仅移除二维码、review、unused 和 source map，不能把全部资源压进首包。需要设计主包、分包、远程资源或压缩方案，并以微信后台当前限额验证。

### 3. 微信工程配置未完成

仓库根 `project.config.json` 当前写入的是抖音 `tt...` AppID 且 `compileType` 为 `miniprogram`，不是最终微信小游戏配置。微信工程应在独立输出目录使用实际 `wx...` AppID 和小游戏类型配置，避免与抖音配置互相覆盖。

### 4. 适配器仍有类型与实现问题

- `src/platform/image.wx.ts` 的类型声明重复 `onload` / `onerror`，需修正。
- `src/platform/router.wx.ts` 使用小程序页面路由思路，而游戏场景并非天然等同小程序 pages；迁移时需按最终引擎重构。
- `src/game/audio.ts` 仍需确认所有实际调用均经过微信音频适配器。
- 当前分享适配器存在，但 UI 是否以用户主动操作触发需在真机版验证。

### 5. 版权证据未闭环

大量美术、配音、BGM 和音效尚未逐项归档生成/购买记录及商用许可。此项在技术完成后仍可能独立阻塞上架。

## 隐私审计

| 项目 | 当前判断 | 提审动作 |
|---|---|---|
| 本地存档 | 有 | 在隐私政策中说明用途和删除方式 |
| 登录/OpenID | 无 | 不声明、不调用 |
| 头像昵称/手机号 | 无 | 不声明、不调用 |
| 位置/相机/相册/麦克风/通讯录 | 无 | `permission` 和 `requiredPrivateInfos` 保持空 |
| 广告/统计 SDK | 无 | 提审包扫描确认无残留 |
| 远程服务器 | 提审目标为无 | 如后续用 CDN，更新政策和备案信息 |
| 外链/二维码 | 仓库有、提审 UI 计划隐藏 | 必须从最终包和截图彻底清除 |

## 当前可接受的首版边界

可以保留：单人剧情、回合制战斗、本地存档、平台允许的主动分享。  
暂不增加：登录、广告、支付、云存档、排行榜、聊天、用户昵称头像、客服表单和任何自由输入。  
原因：这些能力会扩大隐私、内容安全、资质、服务器和审核范围，不适合在首版阻塞项尚未闭环时并行引入。

## 放行标准

只有同时满足以下条件，才能把状态从“材料准备”改为“可提审”：

1. 微信开发者工具可导入并在真机稳定运行完整游戏路径。
2. 首包、分包和远程资源符合平台当前限制。
3. 软著、游戏资质、版号/运营路径、备案、隐私和适龄配置均已取得明确结论。
4. 素材权利可追溯，最终截图、文案与实际代码完全一致。
