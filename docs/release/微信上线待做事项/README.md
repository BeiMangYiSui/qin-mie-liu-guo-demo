目标版本：小游戏 V1.0.0 / 软件著作权 V1.0  
首版方案：无登录、无广告、无内购、无支付、无用户自由输入，本地单机存档

## 先看结论

目前可提前起草的文案、备案信息、隐私政策、用户协议、自审报告、版权承诺、审核体验路径、截图计划和操作清单均已整理。平台账号注册、实名核验、短信核验、手写签名、证书申请、后台提交和最终真机截图只能由开发者本人完成。

当前最大的上架阻塞不是材料文案，而是以下四项：

1. 微信公众平台小游戏账号、个人主体实名和小游戏 AppID 尚未回填。
2. 软件著作权证书尚未取得；现有源码与设计说明底稿可用于申请，但申请前应冻结 V1.0。
3. 当前微信构建目录仍不是可直接运行的原生小游戏工程：入口依赖 React DOM、`document` 和 `window`，且产物约 73 MB，没有完整的 `game.js` / Canvas 运行壳。
4. 美术、配音、BGM 和音效的生成记录与商用授权证据仍需归档；这是当前知识产权风险最高的一项。

## 三种“备案/审批”不要混淆

1. **工信部 APP/小程序备案**：在中国境内提供互联网信息服务的小程序/小游戏需要办理，由微信平台代为向备案系统提交；个人仍需填写真实身份、服务内容、联系方式并完成短信核验。
2. **软件著作权登记**：证明软件权属的重要材料，通常也是小游戏资质审核常见材料；它不是游戏版号。
3. **网络游戏出版审批（版号）**：监管层面的游戏出版运营审批。微信后台对个人、无付费小游戏实际显示的提审材料可能与企业/IAP不同，但平台通道不等于法律豁免。未取得明确合规结论前，不开通支付、内购、广告变现或大规模商业运营。

## 本材料采用的产品事实

- 单人剧情策略游戏，无账号体系、好友、排行榜、聊天或 UGC。
- 仅在设备本地保存关卡、剧情选择、战斗节点、设置和存档时间。
- 不调用位置、相机、相册、麦克风、通讯录、手机号等隐私接口。
- 不接入广告、支付、第三方统计 SDK；不向开发者服务器上传存档。
- 提审版移除微信/Telegram 二维码、B站、机核和其他站外导流。
- 建议适龄标识为 12+，最终以平台审核结果为准。

如最终代码与以上任一事实不一致，必须先更新隐私政策、自审报告和后台个人信息处理清单，再提交审核。
